26// Host-authoritative online play session, relayed through a always-on WebSocket
27// relay server (see docs/relay-protocol.md) rather than direct host<->guest
28// connections. Both host and every guest only ever make ONE outbound connection
29// each, to the same relay - no port forwarding, no NAT traversal, no tunnels.
30//
31// Host: runs the real simulation locally (same as today's local multiplayer),
32// receives InputState from each connected guest and substitutes it for
33// that player's slot instead of reading a physical controller, then
34// broadcasts a SnapshotMsg of every kart's state once per tick.
35// Client: sends its own InputState upstream every tick, and renders using the
36// most recent SnapshotMsg it received from the host instead of running
37// its own authoritative physics for other players.
38//
39// This class only handles the transport + session bookkeeping. Wiring
40// GetRemoteInput()/SetLocalSnapshotSlot()/GetLatestSnapshot() into the actual
41// per-frame controller read & kart tick is a separate, later step.
